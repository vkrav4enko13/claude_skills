# A sketch instead of a description

Read when the user agreed to look rather than read. A sketch is a throwaway hint for one decision — not a prototype, not a mock-up, not part of the product.

## What to do

The cheapest answer to the current question: one HTML file with options side by side (A, B, C) or a diagram — arrangement, navigation, a step's place, states (empty, loading, error), boundaries between parts.

No brand style, final colours and fonts, pixel precision, needless animation, working logic.

Cannot explain the decision clearly in words — too early to draw.

## Where it lies and how to show it

In a temporary folder outside the project. Open it in the browser yourself if the environment allows, otherwise name the full path. No server for a sketch.

## How to ask

Say the sketch is rough, **what to judge** and **what to ignore** ("the order of the steps, not the styling"). Label options with letters.

The answer comes in the chat, not by clicks: "A, B, C or a mix, and what is wrong". A choice among ready options — a blocking question; free criticism — an open one. The chat answer decides.

## If it did not help

The sketch did not close the question, or it came down to finish and motion — that is a prototype question: the step 4 rule on decisions expensive to redo applies.
