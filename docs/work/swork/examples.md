# Acceptance examples темы swork

> Пятнадцать случаев: что произошло, что должно получиться и какое требование это проверяет.

- План из пяти срезов в папке без git → после каждого среза есть копии его файлов; отчёт называет изменённые файлы без обращения к git (проверяет R17, R18).
- Исполнитель вернул «готово», а команда проверки, запущенная основной сессией, падает → статус не ставится, идёт первая попытка исправить; после второй неудачной — остановка, следующие срезы не начаты (проверяет R12, R14).
- Команда проверки среза проходит до единой правки, а названной в срезе функции в коде нет → остановка с сообщением, что проверка ничего не доказывает (проверяет R13).
- Исполнитель добавил параметр «на будущее», которого нет в плане → сверка называет его с цитатой плана, `swork` возвращает состояние до начала, проверки проходят, в отчёте строка «снято» (проверяет R22, R23).
- То же, но после снятия проверка падает → правка возвращена, находка в отчёте в списке «найдено и не тронуто» (проверяет R23).
- Без git исполнитель изменил файл, не названный ни в одном срезе → `swork` находит его по метке времени, останавливается и показывает; вернуть не пытается (проверяет R19).
- Новая функция повторяет существующую в проекте → проверяющий переиспользования называет существующую, основная сессия заменяет, проверки проходят (проверяет R24, R25).
- Проверяющий избыточного предлагает убрать проверку пустого ввода пользователя → правка не делается (проверяет R25).
- Ревью предлагает добавить защитную ветку на случай, которого в обычной работе не бывает → находка отклонена, в отчёте с причиной (проверяет R26).
- Срез S2 с ручной проверкой, от него зависит S3 → остановка после S2. Срез S5 с ручной проверкой, от него никто не зависит → статус «ждёт ручной проверки», работа идёт дальше (проверяет R12, R16).
- Срез меняет схему базы → остановка до его начала (проверяет R12).
- Запрос «переименуй параметр в одном файле» без плана → два предложения в чате, правка, один проверяющий подагент, отчёт (проверяет R5, R28).
- Запрос «добавь систему достижений» без плана → `swork` не исполняет и не планирует, предлагает `splan` (проверяет R5).
- Работа прервана на третьем срезе из шести → при повторном запуске первые два не переделываются, работа продолжается с третьего (проверяет R6, R15).
- Отчёт показан, пользователь ответил «хорошо» → коммита нет, снимок на месте: «хорошо» не выбор шага (проверяет R2, R3, R27).
