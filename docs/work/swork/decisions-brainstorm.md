# Решения темы swork: брейншторм

> Что выбрано в брейншторме, вместо чего и чьё решение.

- Исполнение — свой текст, а не обёртка над `ce-work` и не обычная сессия. Согласился.
- Всё своё: сверка, упрощение и ревью — свои задания подагентам, а не вызов `ce-simplify-code` и встроенного `code-review`. Выбрал пользователь, отменив ранее принятый вызов готовых; цена — задания сопровождать самому.
- «Взять самое лучшее»: приёмы отбираются из чужих скилов по сверке их текстов. Сказал пользователь.
- «Лишнее» — три вещи: дублирует готовое, сделано сверх плана, избыточный код. Выбрал пользователь.
- Работа без git обязательна с первого дня. Сказал пользователь.
- Все семь частей входят в первую версию, урезанной версии нет. Сказал пользователь.
- Срез плана-файла исполняет свежий подагент, а не основная сессия и не выбор по числу срезов. Согласился.
- Срезы только по очереди, без одновременного исполнения даже в git. Согласился.
- Сверка, упрощение и ревью — один раз в конце, а не после каждого среза. Согласился.
- Между этапами остановок нет; остановки только из R12. Согласился.
- Находки `swork` чинит сам в рамках плана, а не только показывает. Согласился.
- Две попытки исправить срез, а не одна и не три. Согласился.
- Ход — в файле плана, а не в отдельном журнале. Согласился.
- Сделанное сверх плана убирается само, если проверки остаются зелёными. Согласился.
- Ручная проверка останавливает работу, только если от среза зависят другие. Согласился.
- Без плана — только малая задача; крупная уходит в `splan`. Согласился.
- Упрощение ищет только переиспользование и избыточное, без эффективности и уровня абстракции. Согласился.
- Малое изменение проверяет один подагент с тремя заданиями, а не четыре и не основная сессия. Согласился.
- Дизайн из трёх частей (копии и откат, ход работы, устройство скила и правки `splan`). Согласился.
