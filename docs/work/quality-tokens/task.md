# Task темы quality-tokens

> Что строим, для кого и как поймём, что получилось.

## 1. Кратко

Три скила меняются точечно. План и исполнитель получают перечень готового кода, чтобы не плодить дубли. Проверяющих становится меньше, а основной текст каждого скила перестаёт выпадать при сжатии контекста. Каждая остановка говорит, что нужно от пользователя.

## 2. Задача

Пользователь хочет от цепочки `sbrain → splan → swork` качества: без лишнего кода и с переиспользованием готового. Затем — расхода токенов, при котором цепочка не сжигает лимиты. Скорость — последней. Сейчас этому мешают четыре вещи:

- исполнитель среза видит только свой пакет и одну строку «поищи готовую», а дубли ищутся уже после написания кода;
- в конце исполнения одни и те же изменения читают четыре проверяющих; в прогоне темы `wiki` упрощение дало 17 находок, применены 3;
- `SKILL.md` у `sbrain` и `swork` — по 44 тыс. байт, у `splan` — 26 тыс.; после сжатия контекста Claude Code оставляет от скила первые 5 000 токенов, и хвост с порядком этапов выпадает;
- часть остановок не говорит, что нужно от пользователя: сводка `sbrain` спрашивается без меню, остановки `swork` не предлагают вариантов.

## 3. Критерии успеха

- На каждое требование есть проверка командой по текстам скилов.
- После всех правок пробная цепочка темы `count` на стенде из `tests/` проходит от требований до отчёта.
- Текст `swork` назначает в конце исполнения двух проверяющих — строки проверки 28 и 30.
- Каждый из трёх `SKILL.md` — не больше 5 000 токенов по замеру.
