# Примеры приёмки темы quality-tokens

> Двенадцать случаев: что произошло, что должно получиться и какое требование это проверяет.

- Срезу нужен разбор даты, и в проекте он уже написан → карточка среза называет готовую функцию с сигнатурой и файлом; исполнитель вызывает её, новой не пишет (проверяет R1, R2, R6).
- Готового для среза нет → в карточке среза стоит, где искали, и «готового нет» (проверяет R3).
- Срез S1 создал помощник, срезу S3 нужен такой же → в пакете S3 есть его имя, сигнатура и файл, текста нет (проверяет R4, R5).
- Малая правка без плана добавляет функцию → до правки `swork` называет в чате, что берёт готовое или где искал (проверяет R7).
- У среза две строки проверки → исполнитель не добавляет своих тестов (проверяет R8).
- Исполнитель видит ошибку в соседней функции → файл не тронут, запись о ней есть в отчёте `swork` (проверяет R9, R10).
- Срезы правили только тексты → читают двое: сверка и поиск ошибок; заданий о дублях и избыточном нет (проверяет R11, R13).
- Изменено пять файлов, проверяющий назвал четыре → пятый назван в отчёте непроверенным (проверяет R14, R15).
- План называет функцию, которой в коде нет → проверяющий плана это находит; порядок срезов он не разбирает (проверяет R16, R17).
- Контекст сжат на этапе сверки → `swork` перечитывает файл этого этапа и продолжает; остановки и запреты по-прежнему в контексте (проверяет R19, R20, R22).
- `sbrain` показал сводку → меню: «Да, записать» с тем, что будет записано, «Поправить», «Ничего не делать» (проверяет R23–R25, R27).
- `swork` показал отчёт → в меню четыре варианта, коммита среди них нет; после «принять работу» отдельное меню предлагает коммит (проверяет R29).
