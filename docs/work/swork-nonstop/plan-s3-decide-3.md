# S3. swork decides instead of stopping — part 3

> What to do in `entry.md`, `snapshot.md`, `finish.md`, `small.md`, and with a user message.

3. `entry.md`: foreign edits → `known.txt` and a `⚠` line; an interrupted "Rollback" slice → establish by the code what ran; unclear → `bypassed`, neither the saving nor the action redone; an unreported manual check → `not checked`; a snapshot without records → continue, never delete it; a done slice red after two attempts → step 2, then `bypassed` without a restore; its `done` dependents stay `done` and are named in the report as built on a broken slice; read `bypassed` statuses first and do not retry them; a legacy `stopped` → red after two attempts.
4. `snapshot.md`: every "a stop" → `known.txt` and a `⚠` line; line 72 → a card edit adding the file.
5. `finish.md`: drop "including the stop"; bypassed and dependent slices are named to every reviewer as "not to be reported as missing"; their findings are dropped and named in "Deviations"; "not checked" slices are treated as manual-only ones.
6. `small.md`: the decisions edit the plan text in the chat; no card, no log card.
7. A user message during the run → the correction is taken from the next step, no menu.
