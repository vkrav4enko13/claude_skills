# Design темы chain-cleanup: скорость и замер

> Раздел 3, одобрен пользователем 2026-10-11: что ускоряем, чем меряем и чего не трогаем.

- **Замер «до».** До любых правок цепочка проходит стенд с настоящими подагентами; записываются минуты по часам, минуты модели, число запусков и токены. Как запускать, решит план.
- **Правки скорости:**
  - подагент читает задание по пути к файлу, основная сессия его не перепечатывает;
  - файл этапа читается один раз за прогон и перечитывается, только если его текста уже нет в контексте;
  - блок PowerShell уходит в отдельный файл;
  - меньше правок карточек на срез: исчезают мёртвые поля;
  - подагенты разведки стартуют одним сообщением;
  - вопросы проверки на пробелы и разделы дизайна в `sbrain` идут одним запросом, по вопросу на раздел.
- **Проба усилия.** После правок исполнители срезов с готовым текстом идут на уровне ниже `xhigh`. Уровень принимается, только если проверки те же и минут меньше.
- **Замер «после».** Тот же прогон. Успех: минут меньше, чем «до», проверки зелёные.
- **Не трогаем:** срезы по одному, два проверяющих, порядок «сверка, затем ревью», повторный прогон проверок перед проверяющим. Выигрыш там мал, а риск для качества есть.

После одобрения раздела пользователь назвал «качество и точность не хуже» главным критерием и разрешил тратить на его проверку больше токенов: замер идёт по три прогона, со слепой сверкой и посевом дефектов — R55–R61 в [требованиях о замере](requirements-quality.md).

Уточнение 2026-10-13: порог «минут меньше, чем „до“» снят, скорость принята как есть — [решение](decisions-translation-measure.md).
