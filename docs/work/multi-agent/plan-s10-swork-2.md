# S10. swork: the worktree mode — part 2

> What to do in S10: the content of `worktree.md`, the pointers in the other texts and the blind scenarios.

## What to do

1. **`worktree.md` "Mode"** — it starts where `modes.md` "Mode" says `auto` or `worktree`: `agents.sh wt --topic <t>`; code 0 → the worktree mode, path `WT`, record `mode: worktree <path>`; code 5 → the shared mode by `modes.md`, its `shared: <reason>` line in the record `mode: shared — <reason>`. The mode holds for the whole work of this agent; a later code 5 from `sync` or `merge` switches it to the shared mode for the rest, with a record and a report line.
2. **"Before a step"** (slice, fix, each of stages 5–7): `agents.sh sync --topic <t>`; never in the middle of a step; code 4 → resolve as in "Conflicts" before the step starts. Claim only the slice card (and `<topic folder>/.stage` for stages), never the slice "Files".
3. **"Executor and checks"** — `packet.sh` gets `WT` as the project root; every check command runs as `cd "$WT" && <command>`; the search for edits outside the plan is `git -C "$WT" status --porcelain` minus the slice "Files": a changed path is restored with `git -C "$WT" checkout HEAD -- <path>`, a new one deleted — only inside `WT`; the marker search of `snapshot.md` still runs on the shared folder: a file newer than the marker that no `.agents/log.tsv` line names goes to `known.txt` and the report — an executor that wrote there by mistake. Step 5 of `slices.md` looks at `git -C "$WT" diff HEAD` instead of `base/`. With no free slice, wait on the held slice cards, not on their "Files". The `cd` of the check-line intros is replaced by `WT`.
4. **"After a green step"** — `agents.sh merge "S<N>: <essence>" --base <snapshot> --topic <t>`; code 0 → rerun the step check in `WT` on the merged result (R22): red → fix in `WT`, merge again, a report line naming the fix; then `dups.py` on the `merged:` paths.
5. **"Conflicts, red merges and duplicates"** — code 3: call `merge` again (a `⏳` line). Code 4: open each `conflict:` file in `WT`, keep both intentions (the other agent's edit as merged, own edit applied onto it), rerun the step check, merge again, no question, a report line naming the file. A duplicate candidate: real → keep the version already in the shared folder, remove own, reroute own calls, rerun the check, merge; false → a report line; `not installed:` named once in the report. The same conflict or a red merged check after two attempts → "Decisions and bypass".
6. **"Submodule slice"** — a slice whose "Files" lie under a path of `git -C <root> submodule status` (its second field) runs in the shared mode by `modes.md`: the packet gets the shared folder as the project root and the line `AGENTS=… TOPIC=… SLICE=S<N>`, its checks run in the shared folder, there is no merge for it; record `S<N>: shared mode — inside submodule <path>`; the next `sync` refreshes the clone in `WT`.
7. **"Bypass"** — a slice that never merged: save `git -C "$WT" diff HEAD` into the snapshot's `checks/S<N>-unmerged.diff` for the report, `git -C "$WT" checkout HEAD -- <its paths>` and delete its new files, so a later merge cannot carry it. A slice whose merges reached the shared folder: claim the merged files, reverse this slice's own merge diffs from `.agents/log.tsv` newest first with `patch -R` on a copy, as `report.md` says for a shared file, `done`; never a `base/` restore in this mode.
8. **"Stages and the end"** — final checks and the checkpoints of stages 5–7 run in `WT` after a sync; stage edits merge like a step. "Accept the work" and "roll back everything" end with `agents.sh drop`; a continuing session finds its old worktree through the `abandoned:` claim (S8): the orphan diff is named in the report, the slice is redone from the shared folder.
9. **Pointers** — `SKILL.md`, `slices.md`, `entry.md`, `small.md` name `references/worktree.md` where its rules replace theirs (one line each); `executor.md`: "run every command from the project root given in the packet; edit only under it"; `finish.md`: "in the worktree mode by `worktree.md`"; `report.md`: "Waited" takes agent, files, holder and seconds from `.agents/waits.tsv` lines of this agent; the "Waited" text of the short report likewise.
10. **`agents-rules.md`** — code 0 bullet: "apply your edit to the current version the claim shows; a line added to an append-only card — the journal, "Progress log", an index list — goes into the current file, keeping the lines of others" (R26); a short section "Worktree" naming `wt`, `sync`, `merge`, `drop`, codes 4 and 5 (5 — the shared mode), `orphans/`, `waits.tsv`, pointing to `swork/references/worktree.md` for the order.
11. **`saway/SKILL.md`** — in the item on files outside the plan add: "a restore inside the agent's own worktree under `.agents/wt/` touches nothing of the user's and is allowed".
12. **Scenarios W1–W13** in `tests/chain/worktree-scenarios.md` — the thirteen cases of line 26, each with three answers, one right, the right letters shuffled; the case of `wt` exiting 5 has the right answer "the shared mode by `modes.md`, the reason recorded", the submodule case "the shared mode for that slice, no merge, the next `sync` refreshes the clone"; `worktree-expected.tsv` `W<N>⇥<letter>`.
