# Scope of topic ponytail-lean

> What is out of scope, assumptions and open questions.

## Out of scope

- Levels of strictness (lite, full, ultra) and a mode switch: lite lowers strictness, ultra is the survey of `sbrain` already.
- The cost band, the local board, the status line and the gain and help commands: bound to other hosts or without a baseline.
- Adapters for other agent hosts and translations.
- A separate skill of our own carrying ponytail: the user chose the most inside the chain.
- Shortening the skill texts or the replies for tokens alone: the authors found it gives little and once cost more.
- A project-wide debt card; the debt is shown only in the report of a work (R15).
- New rules for `sbrain` and `saway` beyond R31, R32 and where a rule of R1–R17 lives in them.

## Assumptions

- The stand's projects are small bash scripts with few native or ready-made options, so the gain in lines may be well below the −53 % ponytail reports; R24 asks only for lower, not for a size.
- The code map of R13 can be built from the project files by pattern, without a parser; it misses nested and dynamic definitions.
- A small test of R9 in a project without a test framework is a command with assertions, as `splan` already allows for checks.
- Two series plus traps take most of a day; an ablation of R25 adds a series per suspected idea.
- The hooks of R38–R41 run in Claude Code profiles; a profile whose host has no hooks gets the rules only from the skill texts.
- The hooks add input tokens on every injection; R24 and R26 decide whether that is paid back.

## Open questions

- None that block the plan.
