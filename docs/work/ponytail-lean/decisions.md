# Decisions of topic ponytail-lean

> What was chosen, instead of what, and whose decision.

- The main gain is less superfluous code, instead of fewer judge violations or fewer tokens — matches the project's first rule, quality without superfluous code and with reuse; user chose; in force
- Tokens and speed are studied too, after quality, instead of code size alone — the user's request "every aspect, including fewer tokens and faster"; user chose; in force
- Quality and accuracy must not suffer, instead of trading them for tokens or speed — the user's words "quality and accuracy must not suffer"; user chose; in force
- Clean room: a reader agent writes an ideas spec, the user reviews it, the writer sees only the spec, instead of two agents without review or taking ideas directly — keeps the source out of our texts and lets the user vet what comes in; user chose; in force
- The ideas spec of 2026-10-17 is the only input of the writer, instead of the source — approved by the user as shown; user chose; in force
- The whole chain is in scope, instead of `swork` alone or `swork` and `splan` — the user's choice; `sbrain` and `saway` get R31, R32 and edits only where a rule lives in them; user chose; in force
- Taken ideas: ladder with scope and root-cause callers, never-cut list, a test for risky logic, `shortcut:` markers with debt, instead of the first three only — user chose all four groups; in force
- The cost band and board, host adapters, translations, the gain and help commands and prose compression are not taken, instead of carrying every ponytail feature — bound to other hosts or without a baseline; agreed; in force
- A code-map script on trial, instead of tokens only through less code or every token idea — the authors themselves did not prove its reuse gain; agreed; in force
- Trap tasks are added to the stand, instead of the current stand only or a real project — our tasks are too small to show less code; user chose; in force
- The rules of writing code have one owner, the executor task of `swork`, instead of a copy in every place — the project's one-owner rule; user chose; in force
- `splan` puts the small test into the plan, instead of the executor adding it — keeps "the executor writes only what is in the plan"; user chose; in force
- All edits are measured together against the current skills, then dropped one by one if worse, instead of a series per idea — two series instead of six or more; user chose; in force
- Five trap tasks with three runs each, instead of three tasks or five runs — balance of signal and series time; user chose; in force
- The code map is built by a script in the packet, instead of the model listing it in the task — a model-made map costs the same search turns; user chose; in force
- Marker `shortcut:` and a "Debt" section in the report, instead of a project debt card in `notes/` — no extra record to maintain; user chose; in force
- Trap tasks run through `splan` and `swork`, instead of the whole chain or `swork` alone — checks both the planned test and the executor's ladder; user chose; in force
- A fresh baseline series on commit `cda6856`, instead of round 3 of quality-zero plus traps — same conditions for both arms; user chose; in force
- Approach B, rules plus a `LADDER:` field in the executor's reply, instead of rules only (A) or the ladder decided in the plan (C) — a step the model at `medium` cannot skip silently; user chose; in force
- Speed is required too: not slower than the baseline, with the speed-up as a goal shown as a number, instead of time recorded only or time that must fall — quality and accuracy stay above it; user chose; in force
- The most of ponytail goes inside the chain, instead of a separate skill of our own or only the four groups — the user's "carry the skill over to the maximum, without loss of quality and accuracy"; user chose; in force
- Review rebuilt by ponytail's kinds, tiers and verdict, and audit rules in the recon of `splan`, instead of the review as it was — part of the maximum transfer; agreed; in force
- Hooks wide as in ponytail — rules at session start, resume, clear, compaction, into every subagent, and a language line before every reply — instead of a narrow trial or no hooks; user chose; in force
- Levels lite/full/ultra are not taken, instead of carrying them — lite lowers strictness, ultra is the survey of `sbrain` already; agreed; in force
- The over-engineering judge, the injected-bug check of planned tests, compressed size and medians are added to the stand, instead of lines and hidden checks only — part of the maximum transfer; agreed; in force
