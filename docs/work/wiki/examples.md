# Acceptance examples темы wiki

> Семнадцать случаев: что произошло, что должно получиться и какое требование это проверяет.

- Правка в одну строку в обычной сессии, вики есть → одна новая строка журнала, новых карточек нет, в итоговом сообщении названо записанное (проверяет R14, R20).
- Сессия только ответила на вопрос о коде → в `docs/` ничего не изменилось (проверяет R15).
- Первая правка в папке без вики и без git → появились `docs/00-index.md` и файл журнала текущего месяца, больше ничего (проверяет R2, R22).
- Сессия запущена в домашней папке и поправила файл настроек → вики не заведена, в итоговом сообщении сказано почему (проверяет R23).
- В проекте `docs/` с документацией для людей → один вопрос, где вести записи; во второй сессии вопрос не повторяется (проверяет R24).
- Проект — игра LGS со своей `wiki/` и правилами в `AGENTS.md` → записи ведутся по правилам игры, `docs/` не появляется (проверяет R25).
- В вики сто строк журнала за три месяца и тридцать тем → новая сессия читает индекс, правила и 10 строк журнала, прошлые месяцы не открывает (проверяет R11, R12).
- Карточка на 45 строк → скрипт её называет, агент делит на две, обе есть в индексе (проверяет R3, R59, R60).
- Пользователь меняет решение, принятое месяц назад → старая карточка получает «заменено» и ссылку, её текст цел; новая — «в силе» (проверяет R10).
- Карточка в `docs/notes/` называет файл, из которого функция уже переехала → агент находит расхождение до правки и исправляет карточку (проверяет R21).
- `sbrain` прерван до сводки → в вики от него ничего нет (проверяет R32).
- `swork` остановился на третьем срезе → `state.md` называет проверенное и следующий шаг; новая сессия продолжает без пересказа (проверяет R30, R31).
- Малая задача через `sbrain` → папки темы нет, строка журнала есть (проверяет R42).
- Пользователь ответил своими словами: «это должен быть корень, если не git — значит не в git» → `sbrain` пересказывает: «записи лежат в корне проекта; под git их коммитит пользователь» — и ждёт «да» (проверяет R50).
- В черновике требование «список открывается быстро» → в карточке «Когда пользователь открывает список, приложение показывает его не позже чем через секунду» (проверяет R45, R51).
- В требованиях двенадцать пунктов, один проверяется только глазами → в карточке проверок двенадцать строк, одна с пометкой «проверяется вручную» (проверяет R55, R56).
- Повторный `install.sh` → блок в общих инструкциях один, текст вне меток прежний (проверяет R64).
