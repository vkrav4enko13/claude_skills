# Как проверять скил до и после правки: факты из документации

> Готового сравнения двух версий скила нет; по умолчанию три прогона на случай; в неинтерактивном прогоне скил не может задать вопрос.

- **`claude plugin eval`** сравнивает «с плагином» и «без» и работает только с плагинами. Личный скил пришлось бы обернуть: манифест с `name`, копии скилов в `skills/`, случаи в `evals/` — code.claude.com/docs/en/plugin-evals.
- **Три прогона на случай по умолчанию:** «One run of a non-deterministic agent tells you little». Судья-модель голосует два из трёх.
- **Порядок проверок.** Сначала проверки кодом, потом судья-модель с подробными критериями; версии сравниваются вслепую — platform.claude.com/docs/en/test-and-evaluate/develop-tests, agentskills.io/skill-creation/evaluating-skills.
- **Прежняя версия как база:** снимок скила до правки и прогон на обеих версиях.
- **`claude -p`.** При `--permission-prompts none` инструмент вопросов убирается. Способа подать ответы в командной строке нет, есть только обработчик в Agent SDK — code.claude.com/docs/en/headless.
- **Усилие.** Скил может просить уровень для вызова подагента; у определения агента есть поле `effort`; уровень сессии задают `/effort` и `CLAUDE_CODE_EFFORT_LEVEL` — code.claude.com/docs/en/model-config.
- **`/fast`:** до 2,5 раза быстрее, то же качество, вдвое дороже, на подписке — кредитами сверх лимитов. Пользователь его не использует.
- **Подагенты.** Одновременно до 20; о записи нескольких в одну папку документация молчит.
- **Сжатие контекста.** От скила остаются первые 5 000 токенов, на все скилы — 25 000.
