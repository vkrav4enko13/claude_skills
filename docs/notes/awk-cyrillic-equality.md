# awk на macOS в локали `en_US.UTF-8` считает равными разные русские слова

> `"правило" == "посев"` в awk даёт 1, пока локаль не `C`: сравнение строк идёт по правилам сортировки, а не по байтам.

- **Как проявляется.** `awk 'BEGIN{print ("правило"=="посев")}'` при `LANG=en_US.UTF-8` печатает `1`; с `LC_ALL=C` перед awk — `0`. Условие вида `$1=="правило"` в такой локали ничего не отсеивает.
- **Где уже задело.** Строка проверки 71 темы `chain-cleanup` на пробном вердикте считает `67 67` вместо `62 5`; строку 9 спасает второе условие с `index`.
- **Где не задевает.** Скрипты `tests/chain/` ставят `LC_ALL=C.UTF-8` сами — в них сравнение верное. Команды строк проверки идут в локали оболочки.
- **Что делать.** В командах с awk, `sort` или `uniq` по русским словам ставить `LC_ALL=C` перед командой либо сравнивать через `index`.
- Источник: срез S4 темы `chain-cleanup`; команды из первого пункта, 2026-10-12
