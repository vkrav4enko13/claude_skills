# На стенде без человека удаление по пути из переменных отклоняется в любом режиме

> Встроенная проверка опасных удалений Claude Code требует явного одобрения; с `--permission-prompts none` это отказ, и его не снимают ни `auto`, ни `--add-dir`, ни песочница.

- **Что отклоняется.** `rmdir "$B/$n"` и `rm` по пути из переменных оболочки; скрипт `bash -c '…'` с `rm`, который проверка не смогла разобрать; составная команда, часть которой требует одобрения. Текст отказа: «It requires approval, and this session has no approval surface».
- **Кто получает отказ.** Подагенты проверки плана, сверки и ревью. Из пяти отказов серии «до» 2026-10-12 уборка временных папок — один; четыре — проверочные скрипты с `rm` или `trap` внутри, отклонённые целиком: часть проверки не состоялась. Без отказа прошли `brain` 5 из 5, `plan` 1 из 5, `work` 1 из 1, `seed` 0 из 2.
- **Проба 2026-10-12.** Три одинаковые команды в четырёх запусках `claude -p` 2.1.296: `acceptEdits`, `auto`, `acceptEdits` с `--add-dir` на временные папки, песочница (`sandbox.enabled`). Команда с `rmdir "$B/$n"` отклонена во всех четырёх; в песочнице ещё и `mktemp` в `/tmp` отвечает «Operation not permitted».
- **Не пробовали.** Режим обхода всех проверок `bypassPermissions`: на рабочей машине он исполнил бы эти удаления без проверки.
- **Что следует для стенда.** Этап засчитывается по достигнутой фазе, отказы считаются в `stage.json` — решение плана темы `chain-cleanup`.
- **Рядом.** Флаг `--restricted` закрывает файловым инструментам всё вне текущей папки: чтение `../key.tsv` даёт отказ.
