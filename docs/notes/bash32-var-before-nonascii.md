# В bash 3.2 имя переменной захватывает не-ASCII знак, стоящий вплотную

> Под `/bin/bash` 3.2 на macOS запись `"$goal»"` читается как переменная `goal»`: с `set -u` скрипт падает; пиши `${goal}»`.

- **Как проявляется.** `/bin/bash -c 'export LC_ALL=C.UTF-8; set -u; goal=x; echo "$goal»"'` отвечает `goal…: unbound variable` и кончается кодом 127. То же с русской буквой сразу после имени.
- **Где не проявляется.** bash 5.3 из Homebrew на той же строке печатает `x»`.
- **Какой bash исполняет скрипты `tests/`.** Проверки зовут их как `bash <скрипт>` — исполняет тот bash, что первым в `PATH`; шапка `#!/bin/bash` и прямой запуск файла дают 3.2.
- **Что делать.** Перед не-ASCII знаком брать имя в скобки: `${имя}»`, `${имя}а`.
